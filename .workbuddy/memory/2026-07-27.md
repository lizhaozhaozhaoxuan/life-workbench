## 修复 supabase/schema.sql 执行报错 (42703: column user_id does not exist)
- 报错点：通用策略 DO 块对所有表统一 `auth.uid() = user_id`，但有两张表结构不符：
  1. `profiles` 主键列是 `id` 不是 `user_id` → `profiles_select` 创建即报错（数组第一个，所以先炸）。
  2. `study_route_nodes` 没有 `user_id`（只有 `route_id`），循环到它也会同样报错。
- 修复：
  1. `study_route_nodes` 增加 `user_id uuid references auth.users(id)`（ALTER ... ADD COLUMN IF NOT EXISTS，幂等），使其符合通用数据层（repo.list 按 user_id 过滤、insert 自动补 user_id，见 db.ts）。
  2. 通用循环数组移除 `profiles`。
  3. `profiles` 单独建 `profiles_select`/`profiles_write`，用 `auth.uid() = id`。
- 用户此前已部分执行（表已建，策略 DO 块整体回滚未建任何 policy），重新完整跑一遍修正后的 schema.sql 即可（IF NOT EXISTS 幂等安全）。
- 教训：凡是走通用 `createRepo` 的表都必须有 `user_id` 列；`profiles` 这类以 `auth.users.id` 为主键的表要单独写策略。
