## Bug 修复：模板里对 computed 直接 Object.keys 崩
- **现象**：页面红字 `TypeError: Cannot convert undefined or null to object`，栈在 `Overview.vue` 渲染函数 `Object.keys($setup.financePie)`。
- **根因**：`<script setup>` 模板中对 computed 直接 `Object.keys(financePie)` 时，`$setup.financePie` 解包路径取到 undefined（dev 运行时），触发 `Object.keys(undefined)`。同模式还出现在 `Overview.vue:243 Object.keys(workoutCatDist)`、`FinanceView.vue:181 Object.keys(expensePie)`。
- **修复**：把这类判断改成在 script 中用 `.value` 算成布尔 computed（`hasExpense`/`hasWorkoutParts`/`hasExpenseData`），模板只 `v-if="hasXxx"`。布尔是原始值，绝不会触发 `Object.keys(undefined)`。已验证编译后无 `Object.keys($setup.` 残留，`vite build` 通过。
- **教训**：Vue 模板里不要对 ref/computed 直接调 `Object.keys/Object.values/Array.xxx`，一律在 script 内用 `.value` 算好再给模板用。

## Bug 修复：生活模块「添加」无响应 + 跨端 crypto.randomUUID 崩
- **现象**：生活模块易忘清单点「添加」无反应（无红字报错）。
- **根因（跨端致命）**：`src/lib/db.ts` 本地/离线 `insert` 用 `crypto.randomUUID()` 生成 ID。该 API 仅在**安全上下文（HTTPS / localhost）**可用；用户手机经内网 IP（如 `http://192.168.x.x:5173`，dev server 的 Network URL 即是）访问时是**非安全上下文**，`crypto.randomUUID` 为 `undefined` → 抛错 → 因在 `async` 点击回调中成为未捕获 Promise rejection，被静默吞掉 = 看起来「点了没反应」。
- **另一诱因**：标题为空时 `addEasy` 直接 `return`（无反馈），也表现为「无响应」。
- **修复**：① `db.ts` 新增 `genId()`，优先 `crypto.randomUUID`，否则降级用 Math.random 实现 RFC4122 UUID（彻底解决手机/IP 添加崩溃，所有模块受益）；② `LifeView.vue` 的「添加」「保存」按钮在标题/名称为空时 `:disabled` + 半透明样式，消除「无响应」错觉。
- **教训**：任何经内网 IP 访问的 PWA，凡用到 `crypto.subtle`/`randomUUID`/`geolocation` 等受限 API 都必须写降级分支；跨端项目默认按「非安全上下文」思维写代码。
- **验证**：`vite build` 通过；dev server 重启后 200。
