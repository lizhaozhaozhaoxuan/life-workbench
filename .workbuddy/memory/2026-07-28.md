## 导入数据部分模块丢失（记账/资产/体重）根因与修复
- 现象：导入本地模式导出的 JSON 后，weight_logs / transactions / asset_* 没写入，前面的表成功。
- 根因：`workout_checkins` 云端表**缺少 `created_at` 列**（建表 DDL 漏建）。本地导出文件该行含 `created_at`，导入云端 insert 报 "Could not find the 'created_at' column"，`importData` 无容错直接抛错中断，导致 TABLES 中排在 `workout_checkins` 之后的所有表（weight_logs→transactions→asset_*）全部未写入。
- 验证：用临时登录账号对导出文件逐表 insert 复现，证实数千据本身可写入，仅 `workout_checkins` 因缺列失败（探测脚本已清理测试数据）。
- 修复：
  1. `supabase/schema.sql`：`workout_checkins` 建表补 `created_at`，并加幂等 `alter table ... add column if not exists created_at`（修根源）。
  2. `src/lib/dataIO.ts`：`importData` 逐行 insert 包 try/catch，单表失败不中断，返回 `failed` 计数与 `errors` 列表。
  3. `src/views/SettingsView.vue`：导入结果提示失败模块。
- 用户侧操作：Supabase 控制台 SQL Editor 执行 `ALTER TABLE public.workout_checkins ADD COLUMN IF NOT EXISTS created_at timestamptz NOT NULL DEFAULT now();`，再到设置页重新导入同一文件（已存在 id 走 skipped，不重复）。
- 教训：导入逻辑必须逐表/逐行容错，绝不能因单条失败拖垮整体；建表 DDL 要与前端 insert 字段严格对齐。

## 交互点击执行成功但需刷新才更新（云端模式订阅 bug）
- 现象：所有模块点击增删改都「无响应」，实际已写入，必须刷新页面才看得到。
- 根因（云端模式）：`src/lib/db.ts` 的云端 `subscribe` 有两处缺陷——
  1. Realtime 回调里写 `void this.list().then(...)`，但箭头函数中的 `this` 并非 repo 对象（`createRepo` 在模块顶层调用，`this` 为 undefined），`this.list()` 抛 TypeError → reload 永不触发。
  2. 云端 `subscribe` 只挂了 Supabase Realtime 频道，完全没监听本用户写操作后派发的本地 `dispatchChange`（window 事件 `lb:change:${table}`），所以自己点的操作 UI 收不到通知，只能靠刷新重新 mount 才 list。
- 本地模式该链路本就正常（subscribe 监听 window 事件）。用户当时跑云端模式才暴露。
- 修复（已与用户确认「双保险刷新」方案）：把云端各方法改为闭包变量 `list/insert/update/remove/subscribe` 返回，彻底消除 `this` 指向问题；`subscribe` 同时 `window.addEventListener('lb:change:${table}')` 收本地变更 + 保留 Supabase Realtime 多端同步；unsub 时双路清理。
- 验证：`npm run build` 通过；dev server `http://localhost:5173` 返回 200，HMR 已热更新。
- 提示用户：多端（手机/电脑）实时自动同步需 Supabase 控制台 Database → Replication 把相关表加入 publication（已开启 Realtime）。本设备即时刷新不依赖 Realtime。

  2. `src/lib/dataIO.ts importData` 增强 catch：① 缺列 → 剥离未知列重试；② 外键孤儿 → 跳过该行（skipped，源数据已失效）；③ 唯一冲突 → 跳过该行（skipped）。

- 教训：本地无外键/唯一约束、云端有，导入时必须对约束冲突做优雅降级；schema 的约束设计要兼容本地多记录习惯。

## Edge Function 部署（stock-quote）——实际环境坑
- ⚠️ `npx supabase@latest` 在 **Apple Silicon (darwin-arm64)** 报错 `No matching Supabase CLI binary package found for darwin-arm64`（npm wrapper 缺该平台二进制），不可直接用。
- ✅ 正确装法（Homebrew，官方 Go 二进制）：`brew install supabase/tap/supabase`。装完 `supabase --version` 验证。
- 部署命令：`supabase functions deploy stock-quote --project-ref jvepeojgareopejdosvm`（ref 取自 `.env` 的 VITE_SUPABASE_URL 主机名前缀）。
- **`supabase login` 是浏览器 OAuth，必须用户本人操作，Agent 无法替其登录**（无账号密码、不能代点授权）。可替代方案：用户生成 Supabase Personal Access Token（Account → Access Tokens），Agent 用 `supabase login --token <TOKEN>` 非交互登录后部署；⚠️ token 敏感，用完建议撤销。
- 协作分三档：① 用户本地 login + Agent 跑 deploy；② 用户给 token + Agent 全自动（含 brew 装 CLI）；③ 只给命令用户自己来。
