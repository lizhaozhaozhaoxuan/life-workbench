## 记账模块小数金额统计错误修复
- 现象：收支流水含小数金额时，统计金额显示脏数（如 `69.99999999999966` 而非 `70`）。
- 根因：前端统计用 `reduce((a,b)=>a+Number(b.amount),0)` 直接累加浮点数，浮点累加误差（如 0.1+0.2=0.30000000000000004）。云端 schema `transactions.amount numeric(14,2)` 本身正确，存储未截断，问题纯在前端展示/统计。
- 修复：`FinanceView.vue` 顶部加 `round2(n)`（四舍五入到分），应用到所有含小数累加的 computed：`monthIncome/monthExpense/expensePie/cashTotal/goldValue/stockValue/investTotal/receivableTotal/payableTotal/assetTotal/netWorth` 以及周度对比 `weekCompare` 的 dTotal/dNet/dLiability。
- 验证：`npm run build` 通过；脚本验证 `1000×0.07` 裸累加=69.99999999999966，round2 后=70。dev server 200。
- 教训：凡前端金额求和必须用 round2/cents 整数法，杜绝浮点累加误差。
- 二次修正（11:15）：仅对 expensePie 做逐次 round2 会导致「各分类之和 ≠ 本月支出总额」（对账不平）。改为 `toCents()` 整数分累加：monthIncome/monthExpense/expensePie/receivableTotal/payableTotal 全部以「分」求和，最后 `/100` + round2，保证分类汇总与总额严格相等。验证 18 笔含小数流水：分类和 241.43 === 总额 241.43。

## 资产模块运行时报错修复（2026-08-09 续）
- 报错1 `categories.reload is not a function`：useCollection 解构漏了 reload，AssetsView 把 items 当成 categories 调 .reload()。已把 reload 一并解构（改名 catReload）并在 onMounted 先 await catReload() 再 ensurePresets()。
- 报错2 `cannot add postgres_changes callbacks ... after subscribe()`：Supabase `supabase.channel(name)` 会复用同名已 subscribe 的频道（HMR / 重复挂载场景），在复用到的旧频道上再 .on('postgres_changes') 必抛此错。修复见 src/lib/db.ts 的 subscribe：每次用唯一频道名 `${table}:${currentUserId}:${genId()}`，订阅前先 getChannels() 清掉同表同用户的残留频道。两种报错均 build 通过 + dev 验证无碍。

## 待买清单保存报错 Promise:[object Object]（2026-08-09 续）
- 根因：AssetsView 的所有 save/remove 处理器（saveCat/saveItem/saveWish/removeCat/removeItem/removeWish）调用 repo 时既未 await 也未 try/catch，云端模式下一旦真实 DB 拒绝（表未建/列/权限等）就变成未处理 Promise 拒绝，只显示无用的 "Promise: [object Object]"，且弹窗照常关闭导致失败被掩盖。
- 修复：抽出 persist()/removeRow() 工具，统一 await + 捕获真实 error 并 alert 明确信息（message/error_description/details），失败不再静默；并给连删二级分类的 removeCat 也加 try/catch。同时 import { type Repo } from '@/lib/db'。build 通过 + dev 验证。
- 注意：该错误本身多为云端表未执行 schema.sql 所致；已改提示后，若再报错会显示真实原因。提醒用户确认 asset_wishlist 等表已在 Supabase 执行。

## 待买保存 invalid input syntax for type date:""（2026-08-09 续）
- 真实根因：未填的预期采购时间 expect_date 被传成空字符串 ""，而 Postgres date 列不接受 ""（只允许 NULL），于是报 invalid input syntax for type date。不强制填写的预期采购时间等可选日期字段需传 null。
- 修复：在 AssetsView 的统一 persist() 里遍历 rest，凡值为空串 "" 一律转 null 再 insert/update。一次性覆盖待买、台账、分类所有可选日期/数值字段（避免 purchase_date / 保修 / 有效期等同样踩坑）。build 通过 + dev 验证。
