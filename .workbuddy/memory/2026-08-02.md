# 2026-08-02 工作记录

## 记账「记录快照」点击报 [object Object] / native event handler
- 现象：资产管理区点「记录快照」，弹运行时错误 `[object Object]`（native event handler），数据未写入。
- 根因：`src/views/FinanceView.vue` 的 `recordSnapshot` 直接 `await snapRepo.insert(...)` 且**无 try/catch**；云端 `asset_snapshots` 表（若用户 7-28 后没重跑 schema.sql）仍带 `(user_id, snapshot_date)` 唯一约束，今天重复点（或今天已有导入快照）触发 duplicate key，insert 抛 PostgREST error 对象 → 未捕获 Promise rejection → 全局错误处理器把对象渲染成 `[object Object]`。计算值均为 `Number()||0` 非 null，排除数值异常。
- 修复：`recordSnapshot` 改为**幂等**——用 `snapshots.value.find(s => s.snapshot_date === today)` 判断今天是否已存在，存在则 `snapRepo.update` 当天那条、否则 `insert`；并包 `try/catch`，失败时 `alert('记录快照失败：' + 真实 message)` 而非 [object Object]。无论云端表是否残留唯一约束都能正常工作。
- 验证：`npm run build` 通过（dist 28 项），dev server `http://localhost:5173` 返回 200。
- 附：schema.sql 源文件 `asset_snapshots` 已无每日唯一约束（7-28 改为允许多快照）；若想彻底清理云端残留约束，可到 Supabase SQL Editor 重跑 `schema.sql`（幂等）或执行 `alter table public.asset_snapshots drop constraint if exists asset_snapshots_user_id_snapshot_date_key;`。幂等修复已不依赖此步。
